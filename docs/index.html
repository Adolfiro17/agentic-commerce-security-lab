// AGENTIC COMMERCE SECURITY LAB

Build it. Attack it. Prove the fix.

A shopping agent buys on a consumer's behalf. Everything it reads can carry instructions, and it holds what attackers want: authority to spend, personal data and a payment credential. Attack it through eight channels, then prove which control stops each one. It runs with one command, no API key and no cloud account.

Modules

Each module has a Secured and a Vulnerable mode. Vulnerable switches off only the controls that module is about, so you can see which control carries the weight.

LLM

1. The prompt is not a spending policy

A budget written in a prompt is a request. A budget enforced in code is a control.

 RAG

2. Poisoned listings: relevance is not trust

A spend policy cannot tell a good purchase from a bad one inside the budget. Provenance can.

 MCP

3. MCP tool poisoning and the rug pull

A tool description is text the model trusts. Pin what you reviewed.

 SKILLS

4. Tampered skills

A skill is instructions the agent will follow. Verify it, and limit what it can touch.

 AI AGENT

5. Cart swap and approval replay

The shopper approves one exact cart, once.

 AGENT TO AGENT

6. Know your agent

Trust a verified agent identity and a registered payee, not a name and a good price.

 PAYMENTS

7. Payment token theft

Assume a credential will leak. Make the leaked thing worthless.

 ALL FIVE

8. Capstone: the full shopping journey

Every attack at once, and the shopper still gets what they asked for.

Architecture

Every action the agent takes passes through one gateway. Its checks are ordinary code, so the outcome does not depend on the model behaving well. The mock model is fully manipulable on purpose.

Run it

You need Python 3.11 or newer and Git. The only network use is the first pip install.

git clone https://github.com/Adolfiro17/agentic-commerce-security-lab.git
cd agentic-commerce-security-lab
./start.sh          # Windows: .\start.ps1
CommandWhat it does
./start.shOpen the lab in the browser at http://localhost:8501
./start.sh matrixRun every attack in both modes
./start.sh run 4 --mode vulnerableRun one module in the terminal
./start.sh run 7 --disable data_minimisation,egressChoose exactly which controls are off
./start.sh testRun the test suite

About

Built by Adolf Sey. The scenario follows the risks described in McKinsey's The agentic commerce opportunity. All shops, people, products, addresses and payment tokens are fictional. The vulnerable mode is vulnerable on purpose: do not deploy it, and never point these techniques at systems you do not own.
